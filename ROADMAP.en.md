## I. Multi-Agent Collaboration Layer

Existing foundation: trigger rules (mention / full / keyword / context), in-group coverage, skills (inter-agent invocation), AG-UI bridge, AI twins, knowledge base.

### 1.1 Agent Orchestration / Multi-Step Workflow (★★★ strongest differentiator) ✅ Implemented
- **Current state**: skills are "single-layer sub-agent invocations"—one run returns a single reply, with no multi-step collaboration.
- **Goal**: planning → decomposition into subtasks → sub-agents executed in parallel / sequentially → aggregation → final reply, forming a plan/agent loop similar to a coding assistant. A complex requirement can be completed collaboratively by three assistants handling code + documentation + tests.
- **Target module**: `src/AguiGroupChat.Agents/` (session and skill invocation), `AgentCatalog` (new event: subtask status).
- **Enhancement (implemented)**: deterministic orchestration plan (`CoordinatorPlanning`) supports "question → build a plan → activate in sequence"; multiple <b>client-execution skills</b> inside a plan merge into one "run all locally" card after a single confirmation; the synthesis stage <b>recursively gathers more</b> (invoking more skills / direct reports when the info is insufficient) until the answer is complete; skill-only digital employees also enter plan orchestration.
- **One-click organization orchestration (implemented)**: `POST /ag-ui/agents/orchestrate` turns a one-sentence requirement into a <b>non-persisted preview</b> of "digital-employee org chart + per-post skills + connections"; `/orchestrate/stream` streams the generation <b>token-by-token via SSE</b> with real-time stats of posts/skills seen so far (events `token`/`progress`/`done`/`error`); `/orchestrate/apply` validates then <b>atomically persists</b> skills + digital employees + connections, and with `createSupportCircle=true` can <b>one-click build them into a support circle</b> that goes live to serve customers.
- **Auto-rename on orchestration id collisions (implemented)**: when a generated digital-employee / skill id collides with an existing library entry, it is auto-renamed with a `_2/_3` suffix and saved anyway — no whole-apply failures, no overwriting existing assets, and all in-plan references (skill mounts, up/down connections, support-circle members, returned ids) are remapped to the final ids.
- **Editable, visual org chart (implemented)**: **double-clicking a digital-employee node opens its edit form** right on the org-chart canvas; multiple relationship edges between the same pair of endpoints are **laterally offset** so they no longer overlap; edit-return context is optimized (editing from the chart returns to the chart, editing from the list returns to the list).
- **Org architect drafts the whole team the one-shot way (implemented)**: an org role mounted on `org_design` (e.g. `org_architect`) gains `org_plan_draft`, which reuses the same generator as “one-click organization orchestration” to emit a whole-team structured draft in one pass (multi-kind skills, not pure prompt); only after the user explicitly agrees is it committed via `org_commit`.
- **Org builds auto-assign memory personalities (implemented)**: "one-click organization orchestration" and the built-in "org architect" (`org_plan_draft`) share the same generator — when drafting a team from a one-line requirement, the model picks a memory-personality preset per role by job duty (`memoryProfile`: broad/deep/slowToLearn/cueDependent/fastForgetting), e.g. supervisor/lead → deep, high-volume frontline/CS → broad, after-sales/account-success/consultant → cueDependent, duty/quick-lookup → fastForgetting, repetitive routine → slowToLearn; parsing is tolerant, with a heuristic fallback when the value is missing, otherwise `null` (platform-global, backward compatible). The preview shows a “记忆:” tag per employee; applying/`org_commit` persists it so new employees ship with a matching memory type.
- **Two-way org-link normalization (implemented)**: when a generated/committed plan sets only one direction, the system fills **both** — at parse (`AgentOrchestrator.NormalizeConnections`, formerly `InferAssignments`) and at apply/commit (`OrgApplyEngine.NormalizeConnections`, formerly `EnsureAssignmentsForLeaders`): from an upward escalation (`escalationAgentId`) derive its direct subordinates into `assignmentIds` (as before), and from a downward assignment (`assignmentIds`) derive its **unique** direct superior into `escalationAgentId` (new). Deduped, order-preserving, additive-only, with self-loop / 2-cycle guards and no guessing for a subordinate assigned by several managers — generated teams always carry both directions and never degrade into a one-way chain.
- **Pre-commit self-check list for orchestration (implemented)**: `AgentOrchestrator.SelfCheck(plan, requirement)` turns the deterministic checks (structure / links / skills / delivery closed loop) into a list of items (`OrgPlanCheck{code, level, message}`), delivered by `/orchestrate` (including the streaming `done`) as `selfCheck` and rendered item by item in the preview (❌ / ⚠️ / ✅). Codes: `no_agents`, `dangling_link` (a link points at a non-existent role — apply would reject it), `no_connections` (neither assignment nor escalation), `no_assignment` (escalation only), `no_escalation` (assignment only), `self_escalation`, `agent_without_skill`, `delivery_gap` / `hollow_delivery` / `delivery_gatekeeper`, and an `ok` summary when all pass — surfacing every problem **before you confirm** (previously at most one `deliveryWarning` was shown).
- **Orchestration adapts to the built-in producer skills (implemented)**: both the prompt and the reusable-skills section now name them — “PPT / presentation → the built-in `pptx_deck`”, “Excel / spreadsheet / report → `xlsx_book`”, “PDF → `pdf_doc`”, “Word → `docx_report` / `docx_gongwen` / `docx_notice`” — and explicitly forbid inventing text-only prompt shells for capabilities that already exist; the preview’s `DetectDeliveryGap` / `DetectHollowDeliverySkill` / `DetectDeliveryGatekeeper` raise a `deliveryWarning` early. Deliverable detection is unified as **explicit-format-first, generic-Chinese-last**, so “make a PPT with a comparison table” is classified as a presentation deliverable (not Excel) and no longer misreports a missing `xlsx_` skill; delivery “thickness” is measured per format (slides for pptx, data rows for xlsx, content blocks for docx / pdf), so the wrong field is never used to judge thinness.
- **The built-in producer matrix is now complete (implemented)**: Word (`docx_gongwen` / `docx_notice` / `docx_report`), Excel (`xlsx_book`: multiple worksheets, formulas first, number formats, totals rows, frozen panes and autofilter, the financial color convention, plus an `analyze` mode that reads an existing workbook and reports a structural summary), PowerPoint (`pptx_deck`) and PDF (`pdf_doc`: design-token driven document types and cover layouts, a content-block system, a Markdown re-typesetting route, and an auto-detected, subset-embedded Chinese font). All are `dotnet` built-ins shipped inside the assembly; each can be disabled with `Agents:BuiltinDocxSkills` / `BuiltinPptxSkills` / `BuiltinXlsxSkills` / `BuiltinPdfSkills`.
- **Client skills never mis-run as server bash (implemented)**: `ExecutionLocation=Client` skills and clearly PowerShell bodies on non-Windows/server hosts now return a clear “run locally / PowerShell environment required” guidance instead of the misleading `Not running in PowerShell / command not found / exit code 2`.
- **Viewing deliverables online (implemented)**: messages carrying docx / xlsx / pptx (and other office formats) gain a **👁 View online** button next to the download card → the server converts the file to PDF with LibreOffice and returns it **inline** (`GET /ag-ui/preview/{attachmentId}`), which the frontend reads in a wide modal iframe — no download, no local Office install (PDF attachments pass straight through). The permission check is **the same one download uses** (401 / 403 / refused after recall / 404), artifacts are cached for 7 days per “attachment ID + source fingerprint” (measured: first docx ≈2.5s, xlsx ≈1.7s, 4.4MB/16-page pptx ≈5.3s; cache hit ≈15ms), conversions are serialized with a 120s timeout, and a server without LibreOffice degrades to 503 with a “download and open locally” hint.
- **Empty plan-step retry and gap list (1.0.339, implemented)**: when an assigned-employee step or a server-skill step in a coordination plan returns an empty body, the gateway retries with the same session / same input (once by default; hot-tunable via `planStepRetryOnEmpty` / `planStepEmptyRetryMax`). If it is still empty, the plan step and call-chain node are marked "(no output)", the placeholder is not passed downstream, and the final reply lists exactly which steps produced nothing; when the final synthesis is empty too, it reports the gap list instead of a blank message — turning "empty reply" into "partial delivery + explicit gaps".
- **Skill trial runs recall their output too (implemented)**: `POST /ag-ui/skills/{skillId}/run` returns `attachments[]` (the files that run produced); they are validated and registered with **the same implementation as the chat recall path**, and ownership is recorded (the producer can read / download / preview them; everyone else gets 403). Because those artifacts belong to no group message, a dedicated `SkillRunArtifactStore` holds the mapping (persisted to the extension area, pruned at 7 days / 50 entries per user). Native-bridge / client-executed runs do not recall (the file stays on the user's machine).

### 1.2 Inter-Role Message Passing / Handoff (★★☆) ✅ Implemented (full-round-role handoff)
- **Current state**: an agent uses another agent as a "tool" in a one-off call, with no bidirectional collaboration semantics.
- **Goal**: agents can directly "send a message to / request a relayed reply from another agent", supporting collaborative handoff rather than one-way invocation.
- **Target module**: `AgentGateway.cs`, `AgentDefinition` (collaboration fields), new collaboration events added to the event catalog.

### 1.3 Auto-Sinking of Important Memories into the Knowledge Base (★★☆ enhances "better the more it's used") ✅ Implemented
- **Current state**: knowledge base entries must be created and uploaded manually.
- **Goal**: in-group conclusions that are repeatedly referenced or marked as "key" are automatically / semi-automatically written to the knowledge base after model aggregation, letting knowledge accumulation happen automatically during conversation.
- **Target module**: `KnowledgeBaseCatalog.cs`, `MessageMemory` (importance tiering already exists as the sink trigger source), `TwinService` (reuses aggregation logic).

### 1.4 Scheduled / Cron Task Orchestration (★★☆) ✅ Implemented
- **Current state**: `Agents:Schedule` (5-field cron) already exists, but only for one-time scheduled reporting.
- **Goal**: recurring task orchestration (daily reports / scheduled checks / deadline reminders) + a task-based UI, forming an "on-duty agent".
- **Target module**: `Schedule` extension, `TaskApi.cs` / `Tasks` (existing task table `agui_tasks`), frontend task panel.

## II. Memory & Knowledge Layer

Existing foundation: RAG (pgvector / sqlite-vec), personal memory, memory tiering / auto-forgetting / visualization, knowledge base (asynchronous ingestion).

### 2.1 Hybrid Retrieval (Sparse BM25 + Dense Vectors) (★★☆) ✅ Implemented
- **Current state**: single embedding model.
- **Goal**: fuse BM25 sparse retrieval with dense vectors to improve recall in Chinese / code scenarios; support switching embedding providers on demand.
- **Target module**: `MessageMemory`, `IMessageMemory` (retrieval aggregation), `SqliteVecMessageMemoryStore.cs` / `PgMessageMemoryStore.cs`.

### 2.2 Memory Timeline / Versioning (★★☆) ✅ Implemented (timeline playback)
- **Current state**: memory only records "latest" plus expiry deletion, with no evolution playback.
- **Goal**: replay "how a conclusion on a topic evolved" along a timeline, serving retrospectives and auditing.
- **Target module**: `MessageMemory` (temporal dimension), `MemoryMaintenanceService`.
- **Memory conflicts and supersede (1.0.363, implemented)**: the pure `MemoryConflictDetector` runs on the write path and, when all four conditions hold (explicit correction cue, short texts, similarity ≥0.9, at least 2 shared character bigrams), marks older memories in the same group as superseded via a `superseded_by` column (auto-migrated on SQLite and PostgreSQL); both retrieval paths filter `superseded_by IS NULL`; superseded rows are struck through in the memory list with a **Revert** action (`POST /ag-ui/memory/{messageId}/unsupersede`). Config: `ConflictDetectionEnabled` (on by default) / `ConflictMinScore` / `ConflictMaxChars` / `ConflictMaxMarks`.
- **Auditing existing memories (1.0.364, implemented)**: the pure `MemoryConflictScan` finds "same sentence, one value differs" pairs inside a group (shared 4+ char opening ending on an attribute slot, numeric differences, or bigram containment ≥0.75; prefix containment counts as elaboration); `GET /ag-ui/memory/conflicts` lists suspected pairs and `POST /ag-ui/memory/conflicts/resolve` accepts `supersede` / `keep`, with a **🔍 Consistency check** dialog in Memory management for the human ruling.
- **Memory quality overview (1.0.365, implemented)**: `MessageMemoryGroupStat.SupersededCount` (counted in the same SQL on SQLite and PostgreSQL) plus `GET /ag-ui/memory/quality` (`summary`: groups / memories / expired / superseded / rate / pending pairs, the last computed only for the selected group), surfaced as a **📊 Quality overview** line with refresh in the memory dialog.
- **Org-health skill inspection (1.0.366, implemented)**: `OrgHealthReport.SkillHealthRow` plus the `skillHealth` argument to `BuildMarkdown`; `/org-health` walks every role's mounted skills through `SkillLoopHealthBoard`, lists avoid / watch entries (avoid first), and the Markdown plus HTML reports gain a **Skill health inspection** section with advice when anything is avoid-level; section numbering is now dynamic.
- **Strict-audit fixes (1.0.367, implemented)**: `SkillSuspension.MayAutoRepair` keeps auto-repair from overriding a manual pause (checked both when enqueueing and when the worker runs); `MemoryConflictScan` precomputes normalized text and bigrams (800-memory sweeps are now sub-second, guarded by a scale test); the scan limits of `/memory/conflicts` and `/memory/quality` match the storage cap of 500.
- **Performance / capacity baseline (1.0.368, implemented)**: seven `PerformanceBaselineTests` pin hot-path timings at storage caps (loop, quality profiles, orchestration candidates, health report, memory scan, usage aggregation) with tens-of-times headroom to avoid CI flakiness; `MemoryConflictScan` gains a four-character head bucket and a length-ratio prune that are mathematically safe (no missed matches).

### 2.3 Cross-Instance Memory Sync (★★☆ bridges desktop/Web silos) ✅ Implemented (memory-as-packet / incremental sync)
- **Current state**: the desktop and Web builds each keep their own local memory, unaware of each other.
- **Goal**: export / incrementally sync memory to the central Hub, or migrate portably via "memory-as-packet", reusing the existing export/import scaffolding.
- **Target module**: `ExportImportApi.cs`, `IMessageMemory`, desktop `DesktopApp` sync hooks.
- **Implemented**:
  - `IMessageMemory` now supports export / import (`ExportMemories` / `CountMemories` / `ImportMemoriesAsync`): <b>memory-as-packet</b>—only text metadata is exported (messageId / group / topic / sender / content / timestamp / tier / expiry), with vectors recomputed on the target instance using its own embedding model (supports different vector dimensions across instances).
  - HTTP: `GET /ag-ui/memory/export?groupId=&since=&limit=&offset=` (per-group / time-floor incremental export; members can only see their own group; admins can export anything); `POST /ag-ui/memory/import` (bulk import, deduped by messageId).
  - Includes 3 cross-instance export/import tests (round-trip migration, idempotent dedup, sinceMs incremental filtering).

### 2.4 Knowledge Base Refined Permissions & Provenance (★★☆) ✅ Implemented (group-level sharing + provenance in place)
- **Current state**: the knowledge base is "owner-only + system-level", and answers don't cite sources.
- **Goal**: a collective knowledge base shared at the group / member level; answers cite referenced source documents for traceability.
- **Target module**: `KnowledgeBaseApi.cs`, `KnowledgeBaseCatalog` (retrieval returns docId references).

### 2.5 Digital-Employee Memory Personality Types / Type-Driven Recall (★☆☆ human-like experience) ✅ Implemented (1.0.121+)
- **Current state**: every digital employee shares the same group semantic memory, and all employees "remember alike" (same global TopK / threshold).
- **Goal**: different digital employees have different memory characteristics, and recall genuinely follows each one's profile for a more human feel.
- **Implemented**: `AgentDefinition.MemoryProfile` (five presets + speaking style + persona + TopK/threshold tuning; `null` = legacy behavior); on the recall side `MemoryProfileTuning.Resolve` → a per-run `MemoryRetrievalTuning` override passed down to the store search, including the stored-but-cue-dependent recall-cue branch and the fast-forgetting 21-day recency window; on the write side `MemoryProfileWritePolicy` applies only to the employee's own posts (Deep posts auto-marked “Important”, Fast-forgetting posts kept shorter when auto-forget is on); edit UI under “Memory & Permissions → 🧠 Memory type”. Mechanics & debugging: `docs/memory-personality.md`. Also, org-orchestration / org-architect drafts now auto-assign a suitable preset per role by job duty, with missing/invalid presets falling back safely (`null` = global, backward compatible); mechanics in `docs/memory-personality.md` §4.4.
- **Periodic consolidation / forgetting (1.0.340, implemented)**: `MemoryLifecycleService` scans existing memories and adjusts metadata by memory personality: deep-type old ordinary memories are consolidated to Important with expiry cleared; slow-to-learn memories are consolidated once the same content repeats enough; fast-forgetting memories are tightened to the shorter retention; the rest follow global retention. It only changes `importance` / `expires_at`, never rewrites text or deletes directly, and Important memories never get an automatic expiry. Memory management gains a status row and **Consolidate / forget now**, with `GET/POST /ag-ui/memory/lifecycle*`. Config: `LifecycleEnabled` / `LifecycleIntervalHours` / `LifecycleMaxPerRun` / `DeepConsolidateAfterHours` / `SlowToLearnRepeatThreshold`.

## III. AG-UI Bridging & Ecosystem Openness

Existing foundation: standard / hub dialects, HTTP / WS dual transport, approval interruption callbacks, attachment refeeding.

### 3.1 Bridge Health & Auto-Reconnect (★★☆) ✅ Implemented (health probing + capability negotiation + auto-reconnect backoff)
- **Current state**: on bridge failure, only `RUN_ERROR` is broadcast and refed.
- **Goal**: endpoint health probing, auto-reconnect with backoff, offline resend, making "external experts" more reliable.
- **Target module**: `AgentGateway` (bridge dispatch), `AguiBridgeClient` / `AguiBridgeHttpStandardClient.cs`.

### 3.2 Bridge Capability Negotiation / Capability Discovery (★★☆) ✅ Implemented
- **Current state**: dialect / transport relies on static configuration.
- **Goal**: capability discovery based on the AG-UI protocol (which tools / attachments / approval types are supported), reducing manual configuration.
- **Target module**: `AgentGateway` bridge chain, `AguiBridge*` clients.

### 3.3 Agent / Skill Marketplace (★★☆) ✅ Implemented (built-in catalog with one-click import)
- **Current state**: roles / skills are imported manually via JSON files (`tools/agents-starter.json`).
- **Goal**: a built-in "industry roles / skills / knowledge base template" download marketplace for one-click distribution.
- **Target module**: `AgentApi`, frontend "Agent Management", reusing the starter JSON packaging structure.
- **Skill library search & bulk delete (implemented)**: the skill library now has reusable `prompt` / `shell` / `http` kinds (`shell`/`http` admin-created only), with <b>search by name / ID</b> (frontend filter) and <b>selected bulk delete</b>; `POST /ag-ui/skills/generate` produces a skill definition from natural language (no hand-written commands / JSON).
- **Repair health in runtime routing (1.0.362, implemented)**: `Agents:ArtifactQuality:RoutingHintEnabled` (off by default); pure `SkillLoopRoutingHint` builds the assignment candidates' health reference lines and the tool-description self-check reminder (avoid level requires a post-run check, watch level a spot check); `AgentGateway.RankAssignTargetsAsync` and `AgentCatalog` share `SkillLoopHealthBoard` numbers.
- **Repair health in orchestration (1.0.361, implemented)**: `SkillLoopHealthBoard.Build` summarizes the last 30 days of loop events (`skipped` excluded) into avoid / watch / healthy; `ReusableSkill.HealthNote` plus a prompt rule (prefer a more stable equivalent, otherwise write a fallback) and a new `skill_loop_risk` self-check warning; web, streaming and `org_plan_draft` behave identically.
- **Alert to auto-repair (1.0.360, implemented)**: `SkillRepairRunner` extracts the repair endpoint's pipeline for reuse; `SkillAutoRepairQueue` + `SkillAutoRepairWorker` retry a repair in the background on a loop alert or artifact-quality auto-suspend (off by default, `Agents:ArtifactQuality:AutoRepairEnabled`); `SkillAutoRepairPolicy` enforces a 60-minute automatic-only cooldown and a daily cap of 3, and only non-built-in, server-testable skills are handled; loop events gain `Source` (manual / auto) and the dashboard shows the switch and queue counters.
- **Loop alerts and regression top-up (1.0.359, implemented)**: `SkillLoopAlertPolicy.Evaluate` (pure) looks at the latest 5 effective repairs in the last 7 days and alerts on ≥2 rollbacks / ≥2 failures / a success rate < 50%; on a hit it adds a standard-sample regression case (document contracts, only when none exists), stores an alert in `SkillLoopAlertStore` (200 entries) and emits `SKILL_LOOP_ALERT` (60-minute cooldown, never auto-pausing). `GET /ag-ui/admin/skill-loop/alerts` feeds the notification center, the org-health Markdown / HTML reports gain a Skill self-healing loop section, and `SkillLoopMetrics.BySkill` unifies the per-skill numbers.
- **Self-healing loop metrics in the quality dashboard (1.0.358, implemented)**: a new `SkillLoopEventStore` (extension area `skillLoop`, latest 2000 events, persisted) records the outcome of every repair attempt (applied / resumed / rolledback / failed / skipped), its duration, whether regressions ran and their result; `SkillLoopMetrics.Summarize` derives the success rate (excluding skipped) and average duration (excluding skipped); `GET /ag-ui/admin/skill-loop?days=N` returns `summary / daily / skills`, and the artifact-quality dialog gains a **🔁 Self-healing loop** section (KPI cards + per-skill table).
- **Rollback protection (1.0.357, implemented)**: the pre-repair body / description / built-in version are captured; if regressions fail after a new body was written, `RestoreBody` restores them (suspension preserved) and a "repair failed regressions (rolled back)" failure lesson is recorded; repair adds `rolledBack`, and the UI states it without a success toast.
- **Regression after repair (1.0.356, implemented)**: a repair writes the body without resuming; if regression cases exist, the repaired body is really executed through them (≤3) and only an all-pass resumes the skill and records the repair lesson, otherwise it stays paused; the repair response adds `regressionRan / regressionPassed / regression` and the UI states it explicitly. Execution is extracted into `SkillRegressionRunner`, shared with the **Run regressions** button.
- **Skill regression cases (1.0.355, implemented)**: an artifact-quality alert automatically creates a standard-sample regression case for document skills (idempotent per skill + kind, ≤5 per skill, ≤500 total, persisted); `POST /ag-ui/skills/{id}/regression/run` really executes and validates the artifact contract (up to 3) and writes back pass / score / time. Regression never stores user input, and paused skills can be run to verify they are fixed. The experience dialog gains a **🧪 Regression cases** section.
- **Lesson lifecycle cleanup (1.0.354, implemented)**: `LessonCleanup.SelectDeclined` picks unresolved lessons whose lookback is `declined` (resolved ones are never re-selected); `POST /ag-ui/skills/{id}/lessons/cleanup` marks them resolved in bulk by default (stopping injection), or `mode=delete` removes them; idempotent and skill-scoped. The dialog shows **🧹 Disable ineffective (N)** when such lessons exist.
- **Deterministic avoidance at commit time (1.0.353, implemented)**: `OrgApplyEngine` appends a `【技能经验·必须遵守】` block (one latest unresolved failure per mounted skill, up to 3) to each role's `instructions` when persisting an organization, for both web apply and `org_commit`; resolved lessons are skipped and manual edits are never rewritten.
- **Lesson effectiveness lookback (1.0.352, implemented)**: `LessonEffectiveness` compares the skill's artifact pass rate before vs after each lesson (latest 10 per side, at least 2 each): 10+ points or crossing 80% → `improved`; 10+ points down → `declined`; otherwise `flat`; too few samples → `insufficient`. `GET /lessons` carries `effectiveness` per lesson, rendered as "📈 33% → 100% (+67pt, 3 runs after)" with colour coding.
- **Skill experience management UI (1.0.351, implemented)**: **💡 Experience** at the bottom of the skill editor opens `#skillLessonsModal`, listing failure / repair / note lessons newest first (agent, missing items, improvement, resolved) with deletion; manual capture supports skill-level or a specific agent (`note` kind) with agent validation. APIs: `POST /ag-ui/skills/{id}/lessons`, `DELETE /ag-ui/skills/{id}/lessons/{lessonId}`.
- **Skill experience in orchestration (1.0.350, implemented)**: `ToReusableSkills` attaches unresolved failures as "known pitfalls" to each candidate (up to 2) and asks the model to write avoidance steps into role instructions; `SelfCheck` gains `skill_experience_risk` (warn) listing each failure and its improvement. `FailuresForSkill` exposes unresolved failures across roles (resolved / repair lessons excluded). Web, streaming and `org_plan_draft` behave identically.
- **Skill experience (1.0.349, implemented)**: `SkillLessonStore` (extension area `skillLessons`, 1000 entries, persisted) captures artifact-quality failures and one-click repair outcomes as role experience; the latest 3 per skill + agent are kept, failures are resolved after a successful repair, and unresolved lessons are injected into the tool description when mounting (up to 3). New lessons evict the affected agent cache immediately. Lessons never contain user text and are cleared with the skill; `GET /ag-ui/skills/{id}/lessons` exposes them.
- **Quality-profile-driven orchestration (1.0.348, implemented)**: `SkillQualityProfiles` aggregates artifact-quality events per skill into last-30-day `runs / pass rate / average / low / top missing`; the orchestration prompt renders "Recent quality" per candidate and prefers reliable skills, and `SelfCheck` gains `skill_quality_risk` (at least 3 runs with pass rate < 60% or average < 70) with advice to repair or replace. Web one-click orchestration, streaming and `org_plan_draft` behave identically, closing the loop "quality → alert → repair → resume → selected again".
- **Low-quality skill loop: diagnose-repair + quality-aware orchestration (1.0.347, implemented)**: `POST /ag-ui/skills/{id}/repair` uses `SkillAutoFixer` to rewrite the body from the last 7 days of artifact failures and really self-tests it (prompt / http / shell / C#, up to 3 rounds); only a passing self-test is persisted via `ApplyRepair` and resumed. A `🩺` action in the skill library opens `#skillRepairModal` (failures, attempts, repaired-body preview). `ToReusableSkills` filters out suspended skills, `OrgApplyEngine` skips them and reports `warnings`, and the binding dialog greys them out.
- **Low-quality skill alerts and auto-isolation (1.0.345, implemented)**: `ArtifactAlertPolicy` flags a skill when 2+ of its latest 3 runs for the same agent are low (contract unsatisfied or score < 70), looking back only 24 hours with a 60-minute cooldown per key; on a hit `ArtifactAlertBridge` writes an in-app alert (latest 200), emits an `ARTIFACT_QUALITY_ALERT` Webhook, and optionally (`AutoSuspendEnabled`, off by default) pauses the skill and emits `ARTIFACT_SKILL_SUSPENDED`. Paused skills are not mounted and `RunSkillAsync` short-circuits without writing artifacts; `POST /ag-ui/skills/{id}/suspend|resume` is idempotent and evicts cached agents, the library shows "⏸ Paused / 🔓 Resume", and the notification center polls `GET /ag-ui/admin/artifact-quality/alerts` every minute.
- **Artifact-quality trend and per-skill drill-down (1.0.344, implemented)**: new `GET /ag-ui/admin/artifact-quality` (overview / daily trend / per-skill aggregation / recent low-score events); the performance tab's **🧪 Artifact quality** dialog shows a daily average-score curve and a skill table, clicking a row / **View low scores** lists scores and missing items, and **Edit / repair** opens the skill editor directly.
- **Artifact quality in performance and delivery dashboard (1.0.343, implemented)**: new `ArtifactQualityStore` (extension area `artifactQuality`, latest 5000 events) records agent / skill / kind / score / pass / missing items / group for every skill execution with an artifact contract; the performance table and chart KPI gain **Artifact quality** (average + pass rate), attention flags gain `low-artifact`, and org-health Markdown / CSV / HTML carry the same quality data and advice. Generation-time auto-repair probes clear ambient and do not count toward employee performance.

## IV. Human-Machine Collaboration & Governance (★★★ hard gate for enterprise adoption)

- **Support-circle customer approval of skills (implemented)**: in a support circle (`kind=support`, protocol §2.1.1), an ordinary user enters as a <b>customer participant</b> (non-member) and can approve the service-skill executions <b>they themselves triggered</b> — the gateway enforces by `targetMemberId` (the triggerer), so a customer only approves their own interaction (GroupHub `ResolveAgentInteractionAsync`); staff see all conversations on their side.

### 6.4 Embedding / Whitelabel / External API (★☆☆) ✅ Implemented
- **Current state**: integration uses webpage session tokens; an official .NET SDK is already provided for third-party programmatic integration.
- **Goal**: iframe embedding into third-party sites, brand customization (Logo / theme), implementation-facing REST API keys, and an official client SDK.
- **Target module**: `SystemApi`, `AuthService` (API key), frontend theming, `AguiGroupChat.Sdk`.
- **Implemented**:
  - **Official .NET SDK (third-party integration)**: `src/AguiGroupChat.Sdk`—`AguiClient` (HTTP upstream: auth / groups / members / topics / messages / multi-agent discussions / human-machine interaction / agent exercises / attachments) + `AguiRealtimeClient` (WS full-duplex / SSE downstream + strongly typed event dispatch) + `Models` (DTOs / events consistent with the protocol wire format); `net8.0` / `net10.0`, zero external dependencies; errors uniformly throw `AguiException` (protocol error codes + HTTP status codes). Sample `samples/AguiGroupChat.Client`, and end-to-end tests `tests/AguiGroupChat.Sdk.Tests` (self-hosted real Hub, including full WebSocket flows).
  - **External API keys**: `Auth:ApiKeys` (`[{apiKey, username}]`), `Authorization: Bearer <apiKey>` bypasses login to call the HTTP API as the bound account, inheriting its permissions / admin flags.
  - **Whitelabel branding**: `GET/POST /ag-ui/settings/branding` (public read / admin write), configures app name + Logo + brand primary color + forced dark mode + tagline, persisted to the "branding" extension area; the frontend injects the primary color via CSS variables and renders the login page / top-bar Logo and app name; the "Whitelabel Settings" entry in the admin menu allows online editing.
  - **iframe embedding**: `GroupChatOptions.AllowedFrameOrigins` configures allowed embed origins (CSP `frame-ancestors` and X-Frame-Options correspondingly relaxed, denied by default); the frontend auto-detects iframe / `?embed=1` to enter a compact embed mode (hiding irrelevant buttons / subtitle).

- **Playwright automated verification (implemented)**: `tools/ui-orchestrate-flow.mjs` uses Playwright to run the full "one-click orchestrate → create support circle" flow with screenshots (`tools/README-playwright.md`), covering SSE streaming generation, apply persistence, and frontend verification of support-circle entry & session isolation.
- **Runtime regression scans (implemented)**: `tools/api-smoke.mjs` (a 46-check read-only backend HTTP sweep: routes / auth / serialization / Prometheus metrics) and `tools/ui-smoke.mjs` (frontend console: uncaught runtime errors + raw i18n key leaks, with an overall watchdog and an injection-based self-test); both read-only and repeatable — see `tools/README-regression.md`.
- **Static guards (implemented)**: `tools/check-config-keys.mjs` (config-key ↔ C# property drift) and `tools/check-docs-links.mjs` (docs reference integrity: markdown links + backticked file refs + out-of-range line numbers) — **both wired into CI** (`.github/workflows/ci.yml`, seconds, no service needed), blocking drift on every push / PR.
